## Inventory boundary and tool counts

This is the pinned upstream inventory. The implemented Hub satellite changes downloads: it writes to a private staging file and preserves an existing destination until exact-size backend completion and atomic replacement. Failed or cancelled downloads discard staging. Its host-file paths must be absolute. The upstream behaviors in the tables below describe the inspected revision, not these Hub changes.

There are **36 implemented tool definitions** in three categories: **15 tab/profile tools, 9 terminal tools, and 12 SFTP tools**. Each category's initialization explicitly registers these tools; the upstream smoke test independently expects `[9, 15, 12]`. [Tab registration](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/tabManagement.ts#L28-L51), [terminal registration](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/terminal.ts#L65-L77), [SFTP registration](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/sftp.ts#L122-L138), [smoke count](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/scripts/smoke-test.js#L11-L20).

Actual `tools/list` visibility depends on settings and installed providers:

| Conditions | Visible definitions |
|---|---:|
| SSH support installed, SFTP enabled, environment detection enabled | 36 |
| Default settings with SSH support installed | 35 |
| SFTP disabled/unavailable, environment detection disabled | 23 |

Environment detection defaults off and its tool is omitted unless explicitly enabled. All `sftp_` tools are omitted when SFTP is disabled, and the category is not registered if `tabby-ssh` cannot load. The remaining tools are not individually switchable in the inspected server filter. [Visibility filter](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/services/mcpService.ts#L43-L55), [module registration](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/index.ts#L78-L86), [defaults](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/services/mcpConfigProvider.ts#L44-L57).

The plugin registers **tools**, not application MCP resources or prompts. The inspected module registers only these three categories, and `createServerForSession` registers only their tool definitions. No resource/prompt registration was found in the bounded `src` and `scripts` source review. This says nothing about SDK-internal protocol behavior. [Server creation](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/services/mcpService.ts#L77-L97).

## Input and output conventions

In the tables, **required fields** are bold; `?` means optional in the input schema. `none` means an empty object. These are upstream names and semantics; they do not yet include a hub `windowId`.

- **Tab locator `T`:** `tabId?: string`, `tabIndex?: number`, `title?: string`. Resolution tries stable ID, then top-level tab index, then the first case-insensitive partial title match. A failed ID can fall through to another supplied locator. No locator normally resolves the focused tab, then the first tab; `close_tab` instead defaults specifically to `app.activeTab`. [Resolver](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/tabManagement.ts#L57-L150), [close default](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/tabManagement.ts#L540-L579).
- **Terminal locator `S`:** `sessionId?: string`, `tabIndex?: number`, `title?: string`, `profileName?: string`. Resolution tries these in that order; textual matches are partial and case-insensitive. No locator selects the first focused split pane found, otherwise the first enumerated terminal; this is not a reliable promise to select the active unsplit tab. A failed supplied ID can fall through to other fields. [Resolver](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/terminal.ts#L271-L310).
- **SSH locator `H`:** the same four optional fields as `S`, but only SSH tabs/panes qualify. A supplied `sessionId` must match exactly and does **not** fall through. No locator uses the first SSH tab/pane. `tabIndex` selects a top-level tab; for a split it chooses the focused pane only if that pane is SSH. [SSH resolver](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/sftp.ts#L282-L372), [shared schema](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/sftp.ts#L490-L495).

IDs are generated and retained in memory for tab/pane objects. They survive tab reordering, not a renderer restart. Terminal `sessionId` is a UUID per terminal pane; tab IDs use a separate short random registry. SFTP delegates session IDs to the terminal category, so an SSH pane has one ID across terminal and SFTP operations. [Tab IDs](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/tabManagement.ts#L53-L100), [session IDs](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/terminal.ts#L40-L91), [SFTP delegation](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/sftp.ts#L254-L264).

Most handlers return one MCP text content block containing serialized JSON, usually with `success` and either result fields or `error`. `get_session_list` instead serializes the session array directly. These application-level failure envelopes should be distinguished from MCP protocol errors. [Tool handlers and session-array return](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/terminal.ts#L349-L396).

Session enumeration traverses top-level terminals and terminal children of split containers, excluding split children whose frontend is not initialized. Each pane is an independent session. The terminal `tabIndex` is a **flattened terminal/pane index**, whereas tab-management and SFTP `tabIndex` refer to top-level tabs. Therefore IDs, not these indices, should form the hub routing contract. [Enumeration](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/terminal.ts#L1272-L1322), [SFTP index lookup](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/sftp.ts#L320-L342).

SSH authentication metadata includes prompt name/instructions, prompt field indices/text, echo flag, a password-name heuristic and response count. It exposes the authentication form through `activeKIPrompt`, which raw PTY input cannot answer. For current Tabby string prompts, echo metadata defaults true rather than guaranteeing the true secret-input behavior. [Prompt inspection](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/terminal.ts#L313-L341).

Waiting command execution supports wrapper syntax for **sh, bash, zsh and fish**. Shell detection uses cached/profile/title/buffer heuristics and falls back to POSIX `sh`; there is no CMD or PowerShell wrapper branch in this source. Cross-platform installation alone therefore does not establish cross-shell execution parity. Interactive/REPL programs should use raw input or non-waiting execution rather than shell-marker wrappers. [Detection](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/terminal.ts#L104-L233), [wrapping](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/terminal.ts#L235-L264).

Buffer mode can lose earlier output when scrollback removes the start marker; the handler returns a truncation warning when it still finds the end marker. Optional stream capture subscribes to `session.output$` during one waiting execution, bypassing scrollback limitations, but accumulates the output until the final tool response. It does **not** expose a continuous output subscription tool or forward raw PTY chunks as MCP notifications. A hub streaming API is additional work. [Capture setup](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/terminal.ts#L497-L557), [buffer capture](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/terminal.ts#L1364-L1464), [stream capture](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/terminal.ts#L1470-L1603).

`waitForOutput:false` sends the command before the active-command registry path. Such commands, manually entered commands, and raw input are absent from `get_command_status`. Active state is a single map entry per session, with no visible mutual-exclusion guard in the handler. A hub should serialize its own waiting executions per pane and avoid promising process-level status or execution replay safety. [Non-waiting branch and registry](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/terminal.ts#L476-L521).

Environment heuristics recognize Python, Ruby, MySQL, PostgreSQL, SQLite, MongoDB, Redis, Node and conventional shell prompts. They are prompt interpretation, not authoritative process inspection; unknown prompt shapes can default to shell. Active detection itself writes to the terminal and is not a passive read. [Heuristics](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/terminal.ts#L852-L919), [active probe](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/terminal.ts#L1026-L1050).

## Multiwindow implications for the replacement

The module obtains renderer-local `AppService` and tool-category instances and starts one HTTP service for that window. Tools enumerate that `AppService.tabs`; there is no window registry or `windowId` field in the 36 schemas. Multiple per-client MCP servers solve client-session isolation within the serving window, not multiwindow aggregation. [Module construction](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/index.ts#L62-L86), [tab enumeration](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/tools/tabManagement.ts#L474-L493), [per-client servers](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/services/mcpService.ts#L23-L36).

Version 1.7.1 includes retry/stale-instance shutdown to reclaim the configured listening port. That can replace an older serving instance; it does not merge both windows' tabs. This qualifies the user's first-window-only observation: the exact winner can vary with lifecycle/handover, but the source still has one listening window's capability scope. [Port retry/handover](https://github.com/GentlemanHu/Tabby-MCP/blob/86a52fdfadb724959929f052c1fc89a45c9f1b0f/src/services/mcpService.ts#L677-L818).

The replacement must retain each tool's **window-local** action while adding explicit global routing. In particular:

1. Namespace live tab/session/transfer/profile identifiers with satellite window/incarnation identity; do not route by global array indices or title substring defaults.
2. Keep the 36 operation names recognizable, but require a window selection for active-tab operations and add stable-ID selectors to index-only operations.
3. Advertise actual installed provider/shell capabilities per satellite; do not claim unavailable serial/SSH support or CMD/PowerShell wrappers as upstream parity.
4. Treat continuous PTY streaming, hub window discovery, reconnect handling, public authorization and an independent daemon lifetime as **new capabilities**.
5. Preserve Tabby-side SSH profiles/connections, local UI approval and file-transfer meaning; proxying MCP does not move those objects into the hub.

These are design implications of the cited handlers and lifecycle, not features implemented by upstream.
